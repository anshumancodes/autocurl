Developers reach for `curl` because it is fast, ubiquitous, and has zero moving parts. It runs everywhere—from your local terminal to containerized CI/CD pipelines.

However, managing more than a handful of curl commands quickly breaks down:
- Shell history is ephemeral and hard to search.
- Scratchpads and Markdown documents suffer from corrupted quotes and unescaped characters.
- Complex JSON payloads and authentication tokens get tangled up in messy shell scripts.

API clients like Postman or Insomnia solve organization, but introduce heavy GUI footprints, account logins, proprietary cloud storage, and massive JSON export files that ruin version control.

**autocurl** delivers the ideal middle ground: automatically discover API routes directly from your backend source code, version-control them as clean, human-readable `.autocurl` files, and trigger requests instantly through an interactive terminal runner.

## Core Philosophy: Three Clear Phases

Instead of forcing you into a proprietary format or bloated GUI exports, autocurl separates your API workflow into three simple, transparent stages:

### 1. Point at Your Backend Project
Run `autocurl ./your-project` against an existing backend (like Express or NestJS). autocurl scans your source files using AST analysis to discover your API routes automatically—no manual request definitions required.

### 2. Version in Plain Text (`index.autocurl`)
autocurl writes an `index.autocurl` file containing clean, HTTP-client-style request definitions—one per discovered route, complete with `@baseUrl` variables, request separators, and source annotations. These files live right in your git repository alongside your codebase and produce clean, readable diffs.

### 3. Run Interactively from Your Terminal
Pass the `.autocurl` file to autocurl: it lists your requests by number, you enter the request number to select it, and autocurl executes the request directly using its built-in HTTP client, displaying status, timing, and formatted responses.

## Postman JSON vs. .autocurl in Git

When teams commit Postman or Insomnia exports to git, even a tiny URL or header tweak generates huge diffs filled with internal UUIDs, timestamps, and deeply nested metadata.

With autocurl, every request is plain text. A one-line URL edit produces a clean, readable one-line git diff:

### Before: Postman Collection Export
```diff
@@ -124,18 +124,18 @@
- "id": "4a71f08e-28c9-4b61-9c88-29bf33ef4a01",
+ "id": "b93c8d10-38e2-47c1-8419-f538e19e0b12",
- "raw": "https://api.dev/v1/users",
+ "raw": "https://api.dev/v2/users",
- "updatedAt": "2026-10-02T18:24:00Z",
+ "updatedAt": "2026-10-03T09:12:00Z"
```

### After: autocurl Plain Text Diff
```diff
@@ -7,2 +7,2 @@
- GET {{baseUrl}}/api/v1/users
+ GET {{baseUrl}}/api/v2/users
```

Your team reviews actual API changes in pull requests—not database schema noise.

## Designed for Developers, Scripts, and AI Agents

Because `.autocurl` files are clean, plain-text HTTP request definitions:

- **AI Agents & LLMs:** Language models can read, generate, and edit `.autocurl` files effortlessly without needing proprietary schemas or heavy JSON wrappers.
- **CI/CD Pipelines:** Automated workflows can inspect and run requests without launching a browser or heavyweight API client.
- **Zero Lock-in:** `.autocurl` files are standard, human-readable HTTP specifications that can easily be inspected, parsed, or ported to standard curl commands or `.http` clients.
