autocurl is designed to be fast, minimal, and transparent: discover routes automatically from your backend codebase, track them cleanly in version control as `.autocurl` files, and execute requests on demand with an interactive terminal runner.

---

## The Two Execution Modes

autocurl inspects the argument you pass and switches modes automatically:

### Mode 1: Generator — Discovering Routes from Source Code

Point autocurl at an existing backend project directory (such as Express or NestJS). autocurl scans source files using AST analysis, extracts your HTTP routes, and writes an `index.autocurl` file in the project root:

```bash
autocurl ./my-api
# Discovers routes and writes index.autocurl in ./my-api/
```

> **Existing File Protection:** If an `index.autocurl` already exists in the project root, autocurl refuses to overwrite it to protect manual edits or existing files. You must rename or delete the file before regenerating.

By default, autocurl uses deterministic AST discovery only. You can enable AI‑assisted analysis with the `--ai` flag:

```bash
autocurl --ai=auto ./your-project   # use AI when additional analysis helps
autocurl --ai=always ./your-project # always request AI-assisted analysis
autocurl --ai=off ./your-project   # deterministic AST only (default)
```

See [AI-Assisted Discovery](#ai-assisted-discovery) for full details.

### Mode 2: Runner — Interactive Terminal Execution

Pass an existing `.autocurl` file to autocurl to launch the interactive terminal runner:

```bash
autocurl index.autocurl
```

> **Single Argument Requirement:** autocurl requires exactly one positional argument: either a project directory to generate from, or a `.autocurl` file to execute.

## AI-Assisted Discovery

autocurl includes optional AI-assisted route analysis to complement its deterministic AST parser. AI is managed entirely by autocurl—you do not need to supply or configure your own API keys.

### `--ai` Modes

| Flag | Behaviour |
|---|---|
| `--ai=off` | *(Default)* Deterministic AST discovery only. No AI requests are made. |
| `--ai=auto` | AI analysis is requested when the AST pass needs additional help (e.g. dynamic route patterns, indirect registrations). |
| `--ai=always` | AI analysis is always requested, even when the AST pass succeeds without warnings. |

You can also set the mode via the environment variable `AUTOCURL_AI=off|auto|always`. A `--ai` CLI flag always takes precedence over the environment variable.

### Managed AI Access

autocurl does not support bring-your-own-key (BYOK). AI credentials and provider configuration are managed internally by autocurl. You never set or configure a Gemini API key.

The CLI sends only bounded, redacted source snippets needed for discovery to the managed API at `https://api.autocurl.lol/v1/scan`. AI scans require a Clerk-authenticated autocurl account. Configure the short-lived account token supplied by the autocurl login flow as `AUTOCURL_API_TOKEN`; configure `AUTOCURL_API_URL` only for local or staging APIs.

AI usage is controlled through your autocurl account and subscription plan. When authentication or quota is unavailable, autocurl reports the managed API error and points to the pricing page. `--ai=off` always remains local and never requires login.

AI candidates must cite supplied source context; invalid, duplicate, or ungrounded suggestions are discarded. AI errors always preserve AST results.

## The .autocurl File Format

An `.autocurl` file is a plain-text HTTP specification format structured into numbered request blocks, separated by `###` markers.

### Anatomy of an .autocurl File

```http
# Generated by autocurl
# Project: my-api

@baseUrl = http://localhost:3000

### 1. GET /health
# @source src/server.js:14
GET {{baseUrl}}/health
Accept: application/json

### 2. POST /organizations
# @source src/controllers/orgs.ts:28
POST {{baseUrl}}/organizations
Authorization: Bearer dev_token_xyz
Content-Type: application/json

{
  "name": "Acme Corp",
  "plan": "pro"
}

### 3. GET /users/{id}
# @source src/controllers/users.ts:15
GET {{baseUrl}}/users/{{id}}
Accept: application/json
```

### Syntax & Formatting Rules

1. **File Header Metadata (`#`):** Comments at the top of the file record metadata, such as `# Generated by autocurl` and `# Project: <name>`.
2. **Variable Declarations (`@name = value`):** Variables defined at the top of the file (like `@baseUrl = http://localhost:3000`) provide default values. They can be referenced throughout requests using `{{name}}`.
3. **Request Block Separators (`### N. METHOD /path`):** Each request block begins with a triple hash `###`, a sequential index, and a label (typically the HTTP method and path).
4. **Source Annotations (`# @source file:line`):** Added automatically during discovery to record the source file and line number where the route was defined.
5. **Request Line (`METHOD URL`):** The primary line of each block declares the HTTP method (`GET`, `POST`, `PUT`, `DELETE`, `PATCH`, etc.) and the destination URL with variable placeholders.
6. **Headers (`Header-Name: value`):** HTTP headers follow immediately below the request line.
7. **Request Body:** Separated from headers by a blank line. Contains the raw request payload (such as JSON).
8. **Variable Placeholders (`{{name}}`):** When parameterized segments like `{{id}}` appear in the URL or body, the runner prompts for values interactively before executing.

## Interactive Terminal Runner

When you run `autocurl <file.autocurl>`, autocurl lists all available requests by number:

```
1. GET /health
2. POST /organizations
3. GET /users/{{id}}
Select request: 
```

### Terminal Controls

| Action | How to Perform |
|---|---|
| **Select a request** | Type the request number (e.g., `1`, `2`) and press `Enter` |
| **Supply missing variables** | When prompted (e.g., `Enter value for id:`), type the value and press `Enter` |
| **Cancel execution** | Press `Ctrl+C` or send EOF (`Ctrl+D` / empty input); exits with code `130` |

### Response Summary & Display

autocurl executes requests directly using Go's built-in HTTP client. When the server responds, autocurl prints a concise, formatted summary:

```
GET http://localhost:3000/users/42
HTTP 200 OK
Duration: 8ms
Response body:
{
  "id": 42,
  "name": "Ada Lovelace",
  "role": "admin"
}
```

- JSON responses are automatically formatted and indented for readability.
- If the endpoint returns an empty body, autocurl displays `Response body: <empty>`.
- Sensitive authorization tokens are kept private and never logged to stdout during execution.

## CLI Synopsis & Options

### Synopsis

```bash
# Discover routes and generate index.autocurl from a project directory
autocurl <project-directory>
autocurl --ai=off|auto|always <project-directory>

# Execute requests interactively from an existing .autocurl file
autocurl <file.autocurl>

# Upgrade your autocurl account (opens browser)
autocurl upgrade

# Display version information
autocurl --version
autocurl -V
```

### `--ai` Flag

Controls AI-assisted route analysis during generation. See [AI-Assisted Discovery](#ai-assisted-discovery) for full details.

| Flag | Behaviour |
|---|---|
| `--ai=off` | Deterministic AST only *(default)* |
| `--ai=auto` | AI used when additional analysis is needed |
| `--ai=always` | AI analysis always requested |

### Exit Codes

autocurl uses standard UNIX exit codes:

| Code | Name | Meaning |
|---|---|---|
| `0` | **SUCCESS** | Request executed successfully, routes generated, or version displayed. |
| `1` | **ERROR** | General error (HTTP/network failure, file read/parse error, or generation error). |
| `2` | **USAGE_ERROR** | Incorrect number of CLI arguments provided (expected exactly 1 argument). |
| `130` | **CANCELLED** | Interactive session cancelled by user (`Ctrl+C` or EOF). |

## Customizing Variables & Environments

Because `.autocurl` files are plain text, managing multiple environments is straightforward. You can edit `@baseUrl` directly at the top of the file:

```http
# Local development
@baseUrl = http://localhost:3000

# Or staging:
# @baseUrl = https://staging-api.example.com
```

You can also define custom variables for tokens or dynamic paths:

```http
@baseUrl = http://localhost:3000
@authToken = dev_secret_token_123

### 1. GET /me
GET {{baseUrl}}/me
Authorization: Bearer {{authToken}}
Accept: application/json
```

## Real-World Examples

### 1. Discovered Express Backend

Given an Express server file:

```js
// server.js
const express = require('express');
const app = express();

app.get('/health', (req, res) => res.json({ status: 'ok' }));
app.post('/api/items', (req, res) => res.status(201).json(req.body));
```

Running `autocurl .` generates:

```http
# Generated by autocurl
# Project: express-api

@baseUrl = http://localhost:3000

### 1. GET /health
# @source server.js:4
GET {{baseUrl}}/health
Accept: application/json

### 2. POST /api/items
# @source server.js:5
POST {{baseUrl}}/api/items
Accept: application/json
```

### 2. NestJS Controller with Path Parameters

Given a NestJS controller:

```ts
// src/users.controller.ts
import { Controller, Get, Param } from '@nestjs/common';

@Controller('users')
export class UsersController {
  @Get(':id')
  findOne(@Param('id') id: string) {
    return { id, name: 'Alice' };
  }
}
```

Running `autocurl .` produces:

```http
# Generated by autocurl
# Project: nest-service

@baseUrl = http://localhost:3000

### 1. GET /users/{id}
# @source src/users.controller.ts:6
GET {{baseUrl}}/users/{{id}}
Accept: application/json
```

When you select this request in the interactive runner, autocurl prompts:

```
Enter value for id: 101
```

And executes `GET http://localhost:3000/users/101`.

### 3. Authenticated Request with JSON Payload

You can add request bodies and headers directly to any request block in `index.autocurl`:

```http
### 1. POST /api/projects
# @source src/projects.controller.ts:18
POST {{baseUrl}}/api/projects
Authorization: Bearer secret_api_token
Content-Type: application/json

{
  "name": "Q4 Performance Initiative",
  "visibility": "private"
}
```
