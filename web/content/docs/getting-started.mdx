This guide walks you through installing autocurl, automatically discovering API routes from your existing backend project, inspecting the generated `.autocurl` file, and executing requests interactively.

---

## Step 1: Install autocurl

autocurl is distributed as a single static binary with zero external runtime dependencies. Request execution is handled directly by its built-in HTTP client.

### Option A: Quick installer (macOS & Linux — Recommended)

Install the prebuilt binary without Go or a compiler:

```bash
curl -fsSL https://autocurl.lol/install.sh | sh
```

The installer supports Linux and macOS on AMD64 and ARM64, installs to `~/.local/bin`, and prints PATH guidance when needed. Set `AUTOCURL_INSTALL_DIR` to choose another destination.

> This command is available once the public binary distribution release is deployed.

### Option B: Homebrew

The easiest way to install and keep autocurl updated:

```bash
brew tap anshumancodes/tap
brew install autocurl
```

To update autocurl in the future:

```bash
brew upgrade autocurl
```

> **Note:** The formula currently points at the private repository's release URL. Repoint it to the public distribution release before using this option; until then, use the installer after deployment or manual downloads from that public release.

### Option C: Manual Binary Download

Standalone binaries are published with each public release for:

| Operating System | Architecture |
|---|---|
| **macOS** | Apple Silicon (M1/M2/M3/M4) & Intel x86_64 |
| **Linux** | x86_64 & ARM64 (`aarch64`) |
| **Windows** | x86_64 standalone executable (`.exe`) |

### Verifying Installation

Check that autocurl is accessible in your shell:

```bash
autocurl --version
```

Output:

```
autocurl v0.1.0-beta.4
```

> **Note:** `dev` is the default build version for development builds. Official releases display their tag.
>
> **Requirements:** autocurl is a self-contained Go binary with zero external dependencies. No external curl binary or runtime environment is required.

## Step 2: Generate routes without AI

The default mode is local deterministic AST discovery. It works offline and does not need an API key:

```bash
autocurl --ai=off ./my-api
```

You can also scan a module directory or individual source file; see [scope generation](/docs/using-autocurl#scope-generation). Optional Gemini BYOK setup and troubleshooting are covered in [Using autocurl](/docs/using-autocurl#ai-assisted-discovery-with-your-own-gemini-key).

## Step 3: Discover API routes from your backend project

Run autocurl against your existing backend project directory (such as an Express or NestJS project). autocurl scans your source files using AST analysis to discover your routes automatically—no manual request authoring required.

```bash
autocurl ./my-api
```

autocurl scans your project, identifies the framework, and writes the output file:

```
Scanning project...

Framework: Express.

Discovered 4 routes.

Generated: index.autocurl
```

> **Existing File Protection:** If `index.autocurl` already exists in the target directory, autocurl protects your changes by refusing to overwrite it: `index.autocurl already exists; rename or remove it before regenerating`.

---

## Step 4: Inspect your generated .autocurl file

autocurl generates an `index.autocurl` file in the root of your project directory. Discovered routes are organized into clean, numbered request blocks with shared base URL variables and source code references:

```http
# Generated by autocurl
# Project: my-api

@baseUrl = http://localhost:3000

### 1. GET /health
# @source src/server.js:12
GET {{baseUrl}}/health
Accept: application/json

### 2. GET /users/{id}
# @source src/routes/users.js:25
GET {{baseUrl}}/users/{{id}}
Accept: application/json

### 3. POST /users
# @source src/routes/users.js:40
POST {{baseUrl}}/users
Accept: application/json
```

Each route entry preserves:
- The HTTP method and endpoint URL with `{{variable}}` placeholders
- The source location where the route was discovered (`# @source file:line`)
- Default `Accept: application/json` headers
- A shared `@baseUrl` definition at the top of the file

---

## Step 5: Pick and execute interactively

Pass your `.autocurl` file to autocurl to launch the interactive terminal runner:

```bash
autocurl index.autocurl
```

autocurl displays the discovered requests as a numbered list:

```
1. GET /health
2. GET /users/{{id}}
3. POST /users
Select request: 
```

Type the number of the request you want to run and press `Enter`.

### Providing Dynamic Variables

If the selected request contains path or query variables (such as `{{id}}`), autocurl prompts you for each missing value before executing:

```
Select request: 2
Enter value for id: 42
```

autocurl resolves the URL, dispatches the HTTP request using its built-in client, and prints the method, resolved URL, HTTP status code, duration, and formatted JSON response body:

```
GET http://localhost:3000/users/42
HTTP 200 OK
Duration: 12ms
Response body:
{
  "id": 42,
  "name": "Ada Lovelace",
  "role": "admin"
}
```
