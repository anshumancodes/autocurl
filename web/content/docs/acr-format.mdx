An `.acr` (autocurl request) file is a human-readable, plain-text format designed to store reproducible cURL requests in version control.

## Anatomy of an .acr File

Every request in an `.acr` file consists of a comment block followed by a standard, multi-line cURL command.

```bash
# 1. Comment header acts as the request label
# Create New Organization
curl -X POST \
  "https://api.example.com/v1/organizations" \
  -H "Authorization: Bearer dev_token_xyz" \
  -H "Content-Type: application/json" \
  -d '{"name": "Acme Corp", "plan": "pro"}'

# Get Current User
curl -X GET \
  "https://api.example.com/v1/me" \
  -H "Authorization: Bearer dev_token_xyz"
```

## Syntax & Formatting Rules

### 1. Request Names
A line beginning with `# [Name]` defines the title of the request displayed in the interactive CLI picker. If omitted, autocurl defaults to the HTTP method and URL path.

### 2. Multi-line Continuations
Commands use standard POSIX backslash line continuations (`\`). This keeps headers and payloads formatted on separate lines for clean git diffs.

### 3. Quoting Standards
URLs and HTTP header values are enclosed in double quotes (`"..."`). JSON payloads and request bodies are enclosed in single quotes (`'...'`) to avoid accidental shell interpolation.

## Why .acr is Superior to Postman JSON in Git

When teams check Postman or Insomnia collections into git, even a tiny URL edit produces a massive diff with generated UUIDs and nested JSON arrays. In contrast, an `.acr` file produces an exact, readable 1-line diff:

### ❌ Postman JSON Export Diff
```diff
@@ -124,18 +124,18 @@
- "id": "4a71f08e-28c9-4b61-9c88-29bf33ef4a01",
+ "id": "b93c8d10-38e2-47c1-8419-f538e19e0b12",
- "raw": "https://api.dev/v1/users",
+ "raw": "https://api.dev/v2/users",
- "updatedAt": "2026-10-02T18:24:00Z",
+ "updatedAt": "2026-10-03T09:12:00Z"
```

### ✔ .acr Plain Text Diff
```diff
@@ -3,2 +3,2 @@ # List users
- curl -X GET "https://api.dev/v1/users"
+ curl -X GET "https://api.dev/v2/users"
```
