Every backend engineer has experienced the frustration of manually assembling curl commands in shell scripts or documentation. From mangled JSON quotes to accidental secret leaks, manual string concatenation is brittle. Here is how modern developers generate reproducible, readable cURL commands automatically.

## The Pain of Manual Curl Command Construction

cURL is the universal lingua franca of HTTP networking. However, when you need to send an authenticated POST request with headers and a nested JSON payload, writing the command by hand in bash quickly becomes error-prone:

```bash
# Brittle manual string escaping in bash:
curl -X POST "https://api.dev/v1/users" \
  -H "Authorization: Bearer "$API_KEY"" \ # Broken quote escaping
  -H "Content-Type: application/json" \
  -d "{\"user\": {\"name\": \"Ada Lovelace\", \"role\": \"admin\"}}"
```

Common issues with manual curl construction include:

- **Escaping hell:** Mixing single quotes, double quotes, and shell variable expansions frequently results in malformed JSON payloads.
- **Secret leakage:** Hardcoding API keys into ad-hoc shell commands pollutes your shell history (`~/.bash_history`).
- **Formatting drift:** Team members format flags differently (`-X POST` vs `--request POST`, `-d` vs `--data-raw`), making pull request reviews noisy.

## The Solution: Code-First Request Generation

Instead of manually stitching strings together in bash or notepad, define your requests as structured data in JavaScript or TypeScript. This guarantees that query parameters are properly encoded, JSON bodies are syntactically valid, and header formatting is consistent.

With **autocurl**, you define an array of request objects in a standard JS file:

```js
// requests.js
export default [
  {
    name: "Create User",
    method: "POST",
    url: "https://api.dev/v1/users",
    headers: {
      "Authorization": "Bearer dev_token",
      "Content-Type": "application/json"
    },
    body: {
      user: {
        name: "Ada Lovelace",
        role: "admin"
      }
    }
  }
];
```

Then generate the clean curl commands with a single CLI command:

```bash
autocurl requests.js
```

autocurl compiles the code into a clean, human-readable `requests.acr` file:

```bash
# Create User
curl -X POST \
  "https://api.dev/v1/users" \
  -H "Authorization: Bearer dev_token" \
  -H "Content-Type: application/json" \
  -d '{"user":{"name":"Ada Lovelace","role":"admin"}}'
```

## Why Generate Curl Instead of Using GUI Export Features?

Many GUI clients offer "Copy as cURL" buttons. While useful for one-off debugging, this workflow does not scale for teams:

- **GUI Export Drawbacks:** Requires opening a heavyweight app, navigating menus, clicking export, and leaves no audit trail or git history. Commands rot as endpoints change.
- **autocurl Generator Advantages:** Version-controlled right in the repository. Running `autocurl index.js` regenerates the entire collection in milliseconds.
