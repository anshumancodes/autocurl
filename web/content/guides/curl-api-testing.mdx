The terminal is where developers spend most of their time. Switching back and forth between your code editor and a bloated desktop API client breaks focus. Here is how to organize, test, and automate API endpoints using cURL and the autocurl CLI.

## Why Test APIs from the Command Line?

cURL has remained the gold standard for network requests since 1997. Modern backend engineers continue to choose cURL for API development for three critical reasons:

- **Speed (Instant Startup):** No loading screens, no framework initialization, zero lag. Requests fire immediately.
- **Portability (Runs Everywhere):** Works over SSH on staging servers, inside Docker containers, and in headless CI/CD runners.
- **Transparency (Zero Hidden Magic):** Inspect exact HTTP headers, TLS handshakes, redirects, and raw byte streams without abstraction.

## The Real Challenge: Organizing Curl Requests

The downside of bare cURL has always been management. When you are building a REST or GraphQL service with 15 different endpoints, keeping track of long curl commands with authorization tokens, JSON payloads, and custom headers in text files is disorganized.

That is why **autocurl** was created: to provide a structured workflow for organizing multiple curl requests inside your project repository.

```bash
# endpoints.acr
# 1. Health Ping
curl -s "http://localhost:8080/health"

# 2. Get User By ID
curl -X GET "http://localhost:8080/users/123" \
  -H "Authorization: Bearer $DEV_TOKEN"

# 3. Update User Plan
curl -X PATCH "http://localhost:8080/users/123" \
  -H "Authorization: Bearer $DEV_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"plan": "enterprise"}'
```

## Two Workflows: Interactive vs Automated Testing

### 1. Interactive Exploratory Testing (Local Development)

While coding a new feature, run `autocurl endpoints.acr`. Use fuzzy search to instantly jump to your endpoint, press Enter to fire the request, and inspect the response output right in your terminal without leaving your IDE.

```bash
autocurl endpoints.acr
```

### 2. Automated Scripting & Smoke Testing (CI/CD)

Execute specific requests directly in automated scripts or pre-commit hooks using the `--run` flag:

```bash
autocurl --run "Health Ping" endpoints.acr
```

## Pro Tip: Inspecting HTTP Status Codes with Curl

When testing APIs from scripts, you can format cURL to output only the HTTP status code using the `-w "%{http_code}"` flag:

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://api.dev/health
```

Returns `200` directly, allowing you to write clean assertion logic in bash or GitHub Actions without external dependencies.
